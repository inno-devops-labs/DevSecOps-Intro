# Lab 10 walkthrough — five minutes

I spent a semester putting a real DevSecOps loop around one app: OWASP Juice Shop. The point was not to collect tools. It was to make the same target safer each week and end with a system that tells you what to fix first.

We started with deploy and threat modeling so we knew what “login” and “checkout” were supposed to do. Then secrets and signed commits, so the repo itself was trustworthy. SBOM plus Grype and Trivy showed how noisy dependency scanning is when you have thousands of components. SAST and authenticated ZAP found problems in code and in the running UI. IaC scans caught Compose and Terraform mistakes before cluster apply. Container hardening and PSS restricted the runtime. Cosign made the image digest the unit of trust, not a floating tag. Falco watched syscalls; Conftest refused bad manifests in CI. DefectDojo was the last mile: one product, one engagement, every report that has a parser.

One finding I actually traced end to end was the class of issues Semgrep reported around Sequelize / injection-style sinks in the Juice Shop API. The scanner pointed at concrete files. That is different from a CVE on an old transitive package you never call. We treated those as “fix or prove unreachable,” not as another row in an 800-finding spreadsheet. On the image side, Trivy Criticals on the running digest were the other queue we would burn a weekend on — because that is what customers download.

Something that did not work: Falco on Docker Desktop for Mac. No host kernel, no real eBPF. The lab looks broken until you move to Colima with a VZ VM. Same class of failure for ZAP into DefectDojo — the importer wants XML, our Lab 5 artifact was JSON. Converting to traditional XML fixed the import. Trivy’s Kubernetes JSON is not Trivy Operator’s format either, so the “Operator” parser returned zero until we mapped it to Trivy Scan. Tools lie about being plug-and-play; the work is format and environment.

If I put one number on a slide, it is **851 active findings after import, with SLA tightened to 3 days for Critical** — and the decision that only Semgrep app sinks plus Critical/High on the running image are this week’s work. The rest is backlog with owners and dates, not a page for the CEO. That is the program: detect early, sign what you ship, watch runtime, and triage with deadlines instead of dashboards.
